# plan.do.see v3 기능 개선 — 보조 검증 기록

> **문서 성격:** v2 → v3 기능 개선 때 생성된 **추가 점검표**로, 과제 6의 별도 필수 제출 파일로 지정된 근거는 확인되지 않았습니다. 과제 6의 제출용 검증 결과는 [verification-checklist.md](verification-checklist.md), 결과물·소스 주소와 제출문 4줄/3줄은 [README.md](../README.md)를 우선 참고하세요.
>
> **오류 표시 정정:** 초기 양식의 `Success / Error`, `Ready / Error`는 검사 결과를 입력하기 위한 **선택지**였으며, 실제 실패나 오류가 여러 차례 발생했다는 기록이 아닙니다. 빈 '실제 결과 / 증거' 칸도 과거 미기록 양식이었습니다.
>
> **증거 경계:** 아래에는 2026-10-26까지 실제로 확보된 DB·소스·사용자 화면 검증만 반영했습니다. 특정 동작의 코드 존재와 실제 UI 재현을 구분합니다. 이 문서 갱신을 위해 데이터를 변경하거나 v3 기능을 추가 실행하지 않았습니다.

## v3 추가 기능 점검 12항목

| 번호 | 검사 동작과 기대 결과 | 확인 결과 / 증거 | 판정 |
|---|---|---|---|
| 01 | 계획 우선순위 변경 → 연결 할 일 순위 전파·계획 이전 버전 보존 | 현재 활성 계획에 연결된 할 일 **7건 전부 계획 우선순위와 일치(불일치 0)**. 계획 변경 버전 6건 보존. 계획 변경 전후를 같은 화면에서 실제로 재실행하지 않음 | **부분 확인** (DB·코드) |
| 02 | 할 일에 계획 연결 → 우선순위 자동 적용·읽기 전용 | `task.create`/`task.update`에 계획 우선순위 상속 코드 존재, 실제 연결 할 일 7건에서 순위 일치. 연결 순간 UI와 읽기 전용 상태의 직접 캡처 없음 | **부분 확인** |
| 03 | 연결 없음 → 할 일 우선순위 독립 수동 설정 | 활성 `plan_id IS NULL` 할 일 **4건** 존재, API에 연결 없는 할 일 독립 우선순위 저장 로직 존재. 독립 우선순위 변경 전후 UI 실측 없음 | **부분 확인** |
| 04 | 계획 삭제 → 목록 제외·원본 계획/실행 로그 보존 | DB에서 계획 **소프트 삭제 1건** 확인, 삭제 로직은 `deleted_at`만 변경. 계획 삭제 버튼 조작 직전/직후 및 특정 계획의 로그 보존 전체 재현은 미실시 | **부분 확인** |
| 05 | 돌아보기 한쪽만 작성 → 주간 카드 1장·빈 섹션 미표시 | 주간 기록 **3건** 보유. 두 필드 모두 입력된 기록 2건, 두 필드 모두 빈 기록 1건. **한쪽만 작성·빈 섹션 숨김 UI 시험은 미실시** | **미실시(해당 UI 사례)** |
| 06 | 같은 주 재저장 → 기존 카드 갱신, 중복 없음 | DB 주간 기록 3건, **중복 주차 0건**. 재저장 버튼 연속 조작 전후 기록은 미보관 | **부분 확인** |
| 07 | 다음 주 이동 → 새 작성란·미작성 경고 없음 | 여러 주차의 DB 기록 존재. 다음 주 이동 후 초기화되는 입력창과 경고 부재는 직접 기록된 실험 없음 | **미실시(해당 UI 사례)** |

| 09 | 자주 쓰는 색상 → 선택·저장·새로고침 후 재사용 | DB 색상 기록 **10개** 존재. 동일 색상이 UI에서 새로고침 후 재사용되는지 전후 화면 실측 없음 | **부분 확인** |

| 11 | 과제 C21·C22 → 완료 두 번 클릭 시 중복 기록 없음 | 사용자 실제 화면에서 완료 버튼 연속 2회 클릭 후 중복 증가 없음 확인, Supabase 후속 확인에서 해당 할 일 완료 이벤트 **1건** | **통과(검사 범위 내)** |

## 제출 여부와 추가 검증 필요성

- **과제 6 제출물(확인된 기준):** 결과물 주소, 소스 주소, 짧은 확인 방법 4줄(C59), AI와 내 판단 3줄(C60). `evidence/v3-verification.md`를 **별도 제출할 의무가 있다는 근거는 확인되지 않음**. 정확한 원본 과제 안내 외 별도 공지가 존재한다면 그 조건은 별도로 따르세요.
- 이 파일은 소스 저장소 내부의 **보조 증거 문서**로 보존합니다. 12개 v3 세부 UI 시나리오 중 일부는 직접 테스트하지 않았으므로, 전체를 무조건 통과 처리하지 않습니다.
- 위에서 '미실시'라고 적힌 항목은 **v3 보조 검증의 잔여 UI 테스트**를 뜻하며, 과제 6 핵심 제출 요건 미충족으로 단정하지 않습니다.
- 실사용 데이터는 사용자가 **모두 공개 가능한 내용**이라고 2026-10-26 직접 확인했습니다. 이는 사용자 확인이며 제삼자 정보 전수 조사 결과는 아닙니다.
