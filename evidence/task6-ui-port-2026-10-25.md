# 과제 6 ← 과제 7 UI 이식 검증 기록 (2026-10-25)

## 범위와 작업 브랜치
- 소스: 과제 6 `main` → `port-task7-ui-no-auth` (Draft PR #1).
- 비교 대상: 과제 7 `main`의 `index.html`, `style.css`, `app.js`과 과제 6의 같은 파일.
- 운영 `main`, 운영 Supabase 데이터, Production 환경변수 및 기존 사용자 기록은 변경하지 않음.
- 과제 6의 공개 REST API `/api/state`, `journal.save`, `reflection.next`, `pds_weekly_reviews` 유지. Neon 인증·계정별 데이터·5일 관찰 기능을 이식하지 않음.

## 적용한 UI/오류 수정
1. 시간 기록: 파란 메인 링 및 100% 초과 시 민트색 외부 링, 예상/실제 범례, `h/m` 단위, 실제−예상 차이(부호 포함), 상대 차이 막대, 수치→근거 기록 버튼. 비율은 시간 사용량이지 목표 달성률이 아님.
2. 계획 돌아보기: 60:40 반응형 카드 레이아웃, 네 개의 집계값/근거 기록, 통계+작성 영역 접기/펼치기.
3. 할 일 목록·사이드 패널: 우선순위 색상과 분류 배지, 텍스트 대비 자동 선택, PLAN/OPTIONS/WHEN/COLOR 구역, 오늘/이번 주/직접 지정/반복 일정 선택. 기존 서버 필드 `mode,start_date,end_date`를 사용함.
4. 저장 오류 수정: `오늘의 작은 발견`과 `다음에 다르게 해볼 것`은 **서버 저장 성공 후** 편집창에서 지워지고, 새로 렌더링할 때 저장값을 다시 채우지 않음. 별도 `나의 기록` 카드에는 저장된 내용을 그대로 보존.
5. 두 필드 중 한쪽만 입력해 저장할 때, 다른 쪽의 기존 저장값을 빈 문자열로 덮어쓰지 않음. 작성란이 비어 있어도 기존 카드의 `다음에 다르게 해볼 것`을 다음 계획 연결에 사용할 수 있도록 수정.
6. 공개 첫 화면 경고문구 유지. `authGate`, `auth-ui.js`, `experiment.html`는 이식하지 않음.

## 동일하지 않은 점과 이유
- 과제 7의 **일별** 기록(`pds_daily_journals`)은 과제 6에 없고, 과제 6은 **주별** 저장(`pds_weekly_reviews`)을 유지함. 따라서 카드 저장 주기는 과제 7과 동일하지 않음.
- 과제 7의 `MY FIRST STEP` 저장 필드는 과제 6의 Supabase `pds_tasks` 스키마/서버 쓰기 API에 없으므로 이 PR에서는 도입하지 않음. 데이터베이스 마이그레이션 없이 보이는 입력창만 만들면 저장되지 않는 오류가 되기 때문.
- 과제 7의 개인 JSON 가져오기·계정 삭제·인증 분리 기능은 제외함.
- 과제 6 기존 자료와 계약을 보존하기 위해, 과제 7 코드를 파일 단위로 덮어쓰지 않고 UI 부분을 선택 이식함.

## 수행한 소스 검사
- `app.js` JavaScript 구문 컴파일 통과 (`new Function` 구문 검사).
- 새 HTML에서 필수 DOM ID가 모두 존재하고 중복 0건임을 대조함.
- 공개 경고문구가 로그인 없이 보이는 첫 화면의 상단에 남아 있음.
- 과제 6의 Supabase API 소스는 변경하지 않았으며, 회원가입·로그인·5일 관찰 링크가 새 HTML에 없음.
- 시간 링 및 계획 돌아보기, 입력칸 초기화/기존값 보존을 위한 `tests/ui-port.test.mjs` 작성.
- 기존 `tests/browser-v3.py`를 Task 7 UI 버튼·시간 요약·숨김 패널·일정 선택 UI에 맞춰 갱신함. **브라우저 자동 검사 실행 성공은 아직 확인하지 않음.**

## 배포·실데이터 확인이 막힌 부분
- Vercel 과제 6 프로젝트의 환경변수 목록 조회 결과 `SUPABASE_URL`은 Production/Preview에 있으나 **`SUPABASE_SERVICE_ROLE_KEY`는 Production에만** 있음. 따라서 신규 Preview에서 서버가 실제 Supabase 데이터를 읽고 저장하는 동작은 미검증. Preview를 운영 DB에 연결하기 전에 테스트 DB와 별도 자격증명을 마련하는 편이 안전함.
- 운영에 이미 배포된 원래 버전과 DB/기록은 변경하지 않음. 브라우저 실화면 및 반응형 레이아웃, 실제 입력·저장·새로고침·JSON 파일 비교는 추가 실측 필요.
- `evidence/verification-checklist.md`는 기존에 모든 행이 `미검증`인 **기록 양식**이다. 코드 존재만으로 각 항목의 실제 통과를 선언하지 않음.
